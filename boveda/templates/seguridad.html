Cómo protege Bóveda tus datos

Cada mecanismo usa un algoritmo estándar de la librería cryptography de Python. Ningún algoritmo está implementado a mano.

Mecanismos

MecanismoAlgoritmoUso en la aplicación
Cifrado simétrico AES-256-GCM con nonce aleatorio de 96 bits Título y texto de cada documento. Se guardan cifrados en la base de datos.
Firma asimétrica Ed25519 (RFC 8032) Sello de cada documento y certificados que cualquiera puede verificar.
Derivación de claves HKDF con SHA-256 (RFC 5869) Separa la clave maestra en una clave de datos y una clave de sesión.
Contraseñas scrypt con N=217, r=8, p=1 (RFC 7914) Verificación al iniciar sesión y clave que abre la llave de firma.

Dónde vive cada llave

LlaveDónde estáCómo se protege
Clave maestra, 256 bits Variable de entorno BOVEDA_CLAVE_MAESTRA o archivo fuera de Git Nunca entra a la base de datos ni al código. El archivo solo lo puede leer tu usuario del sistema.
Claves de datos y de sesión Solo en memoria mientras la aplicación corre Se derivan de la clave maestra con HKDF. Una clave distinta por propósito.
Llave privada de firma, por usuario Columna clave_privada_cifrada de la base de datos AES-256-GCM con una clave derivada de tu contraseña. Solo se abre al firmar.
Llave pública de firma, por usuario Columna clave_publica_pem No es secreta. Quien la verifica compara su huella SHA-256.

La huella identifica la clave sin revelarla. Si la clave cambia, los documentos existentes no se podrán leer.

Límites conocidos

  • Quien tenga la clave maestra puede leer todos los documentos. Por eso no debe estar en el código ni en el respaldo de la base de datos.
  • Si olvidas tu contraseña no podrás firmar, porque tu llave privada no se puede recuperar.
  • La aplicación corre en HTTP local. En un servidor real, pon TLS delante y activa BOVEDA_COOKIES_SEGURAS=1.
